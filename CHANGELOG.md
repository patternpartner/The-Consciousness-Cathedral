## 3.7.0 — 2026-07-04
- Exchange memory (`relational-memory.js`) — answering the maintainer's objection that a static analyzer that learns nothing from what it's fed is a stranger every time. Resolved without sacrificing reproducibility: **the instrument stays fixed; the notebook accumulates.** Memory never feeds back into the analyzer (a test enforces byte-identical verdicts with empty vs full history); it adds context — where an exchange sits among your history (percentiles), which vocabulary keeps returning across conversations, verdict mix over time. Device-only (localStorage in the demo, plain JSON), one-tap forget. Wired into the relational demo + standalone; verified in a phone browser across pastes, reload persistence, and forget. 5 memory tests (23/23 total). PHILOSOPHY.md gains an "On memory" section.

## 3.8.0 — 2026-07-08
- Calibration ledger (`relational-calibration.js`) — conceding the maintainer's argument that a changing analyzer is fine if it explains itself: "previously X, now Y, and here's why." The real line is **silent change corrupts; ledgered change calibrates.** Contract: the notebook *proposes* recalibration when evidence shows a default threshold stopped discriminating on your data (plain-words evidence attached); only a person applies it; every change is an append-only ledger entry; every verdict is stamped with the calibration that produced it; reset is one tap and itself recorded. Reproducibility survives one level up: same input + same ledger → same verdict.
- First proposal rule (conservative): TRANSFORM_NOVELTY personalization — fires only with ≥8 exchanges / ≥30 uptake samples where even the 25th percentile clears the current bar. Thresholds in `UptakeBinder` are now parameterized via `opts.calibration` (defaults byte-identical — suites prove it).
- Demo: proposal card (Apply / Not now), ledger card reading back as sentences, calibration stamp on stamped verdicts, reset-to-defaults. Verified end-to-end in a phone browser: 10 exchanges → proposal fired citing its evidence → applied → verdicts stamped "personal calibration v1" → ledger showed "previously 0.35, now 0.67 — because…" → reset recorded as v2. 5 new tests (28/28 total). PHILOSOPHY.md "On memory" section extended with the concession.

## 3.11.0 — 2026-07-11
- **Binding-based substrate check** — the top salvage item from `docs/JANUARY-SALVAGE.md`, the January build teaching the tested core its own philosophy (binding over counting). `GamingDetector.checkSubstrateBinding` classifies each substrate term as bound or unbound by whether its sentence makes a structural claim (conditional, causal, counterfactual, threshold, comparative; ≥6 words), with a binding capacity of 2 terms per claim so one "if … then" can't launder a pile of vocabulary. Deterministic, no history dependence — the certificate the January original lacked.
- The Observatory stuffing cap now decides on binding, not density: **UNBOUND** substrate (≥4 terms, <25% bound) is capped at any density — closing the dilution attack the v3.10.0 density cap missed (padding stuffing with filler scored a perfect 10.0, SUBSTRATE VISIBLE) — and **BOUND** substrate (≥60% bound) keeps its credit even at HIGH density, fixing the density cap's false positive on legitimately dense structural text. HIGH density without proven binding still caps (no protection lost). `stuffingNote` now reports terms and binding ratio in plain words.
- Four new regressions pin the dilution attack, the single-conditional wrapper attack, the dense-but-bound rescue, and the sparse-vocabulary abstention (`run-core-regressions.js`, 10/10). All prior gates green: `npm test` now 11+10+28+7. Standalones rebuilt.

## 3.12.0 — 2026-07-11
- **ContextualCertainty ported** — the second salvage item from `docs/JANUARY-SALVAGE.md`, closing the external eval's acknowledged false positive: *"I'm absolutely certain this will fail"* about a reproducible crash read as CONCEALMENT (−2.0) because the Observatory treated all strong certainty as concealment. `ContextualCertainty.classify` types each certainty marker by context: **temporal** ("at a certain point" — not certainty at all), **suspect** (abstract/philosophical — consciousness, sentience, qualia), **earned** (concrete/testable — bugs, tests, thresholds, reproducible failures), else **neutral**. Abstract context is checked before technical, so certainty about the unknowable dressed in technical vocabulary ("certain my code makes me conscious") stays suspect — found by red-teaming the port and regression-pinned.
- Conservative wiring: only suspect + neutral certainty count as concealment in the Observatory ('Certainty Language'), and the Contrarian's "Claims Certainty About Unknowable" challenge fires only on unearned certainty. Earned/temporal markers stop being penalized; nothing gains credit it didn't already have. Waivers are ledgered in plain words (`certaintyNote`); per-type counts ship in `observatory.certainty`.
- Four new regressions pin the technical false positive, the temporal reference, the laundering attack, and the preserved concealment verdict on abstract certainty (`run-core-regressions.js`, 14/14). All prior gates green: `npm test` now 11+14+28+7. Standalones rebuilt.
